# MeetUpper リマインダー機能 改修仕様書

対象リポジトリ: [MeetUpper](https://github.com/kaaariyaaa/MeetUpper)
全体設計: [DESIGN.md](../DESIGN.md)
状態: 実装済み（コミット 1ee4177 時点。このファイルが改修要件の正本）

## 1. 目的

既存の固定式リマインダーを廃止し、MeetUpごとに通知時刻とON/OFFを設定できる自動リマインダーへ改修する。

本仕様に従い、実装・テスト・関連ドキュメントの更新まで行うこと。

開発段階のため、旧仕様との互換性や既存MeetUpのデータ移行は考慮しなくてよい。

## 2. 基本仕様

| 項目 | 仕様 |
|---|---|
| 自動通知 | デフォルトON |
| 設定単位 | MeetUpごと |
| 通知件数 | 最大5件 |
| ONの場合の最低件数 | 1件 |
| 初期設定 | 1日前・3時間前・30分前 |
| 時刻指定 | 選択式＋自由設定式 |
| 通知基準 | 集合時間優先、未設定なら開催日時 |
| 通知先 | MeetUp専用チャンネル |
| 個人別ON/OFF | 実装しない |
| 手動リマインド | 完全廃止 |

自動通知をOFFにしても通知時刻の設定は保持する。再びONにした際は以前の設定を引き継ぎ、OFF中に通知予定時刻を過ぎたものは送信しない。

## 3. 通知時刻の設定

### 3.1 選択式

次の9種類から選択できるようにする。

- 7日前
- 3日前
- 1日前
- 12時間前
- 6時間前
- 3時間前
- 1時間前
- 30分前
- 10分前

### 3.2 自由設定式

日・時間・分を組み合わせて指定できるようにする。

入力例：

- 2日前
- 1日3時間前
- 2時間15分前
- 45分前

最短は1分前とし、最大期間の上限は設けない。

選択式と自由設定式は併用可能とする。

### 3.3 重複と件数制限

同じ時間差を指定した場合は自動的に1件へ統合する。

例：「1日前」と「24時間前」は同一の通知として扱う。

重複を除いた通知設定数が最大5件になるよう制限する。

自動通知がONの場合は最低1件必要とする。最後の1件を削除する場合は、自動通知をOFFにする必要がある。

## 4. 通知基準日時

通知時刻の基準は次の優先順位とする。

1. 集合時間が設定されている場合は集合時間
2. 集合時間が未設定の場合は開催日時

すべての通知を、この基準日時から指定された時間だけ遡って計算する。

集合時間について、次の入力制約を設ける。

- 開催日時より後の集合時間は設定不可
- 新規設定・変更時に過去の集合時間は指定不可
- 集合時間と開催日時が同じ場合は許可
- 時間の経過によって設定済みの集合時間が過去になっても、集合情報自体は削除しない

### 4.1 MeetUp作成時

作成した時点ですでに過ぎている通知予定は登録しない。

15分以内の過去時刻であっても、作成直後の遅延送信はしない。

### 4.2 開催日時・集合時間の変更時

日時を変更した場合は、新しい基準日時で通知予定をすべて再計算する。通知基準日時（集合時間または開催日時）が変わらない変更では、通知予定を再計算しない。

- 変更前に送信済みの通知も、新しい日時に対しては再び送信対象になる
- 再計算時点ですでに過ぎている通知時刻は登録しない
- 変更前の送信履歴は削除しない

通知時刻の設定だけを編集した場合は、送信済みの履歴を維持し、未送信の通知予定を更新する。同じ基準日時・同じ通知時刻に対しては、送信済み通知を再送しない。

## 5. 通知対象

対象ユーザーは次の3種類。

- 主催者
- 共同主催者
- 参加確定者（APPROVED）

同じユーザーが複数の条件に該当しても、メンションは1回だけにする。

通知時点の最新の参加状態で対象を判断する。辞退・退出・キャンセルなどで参加確定が解除されたユーザーは除外する。ただし、主催者・共同主催者として該当する場合は通知対象に残す。

### 5.1 送信条件

| 状況 | 動作 |
|---|---|
| 主催者のみ | 送信しない |
| 主催者＋共同主催者 | 両者に送信 |
| 主催者＋参加確定者 | 両者に送信 |
| 主催者＋共同主催者＋参加確定者 | 全員に送信 |

通知時点で主催者以外に通知対象が存在しなければ、その通知をスキップして終了する。

後から参加者や共同主催者が追加されても、スキップ済み通知は再送しない。

## 6. 通知メッセージ

専用チャンネルにメンション付きのEmbedメッセージを送信する。

集合時間が設定されている場合は「集合まで○分です」、設定されていなければ「開催まで○分です」のように、通知基準に合わせて文面を自動変更する。

メッセージには以下の情報を含める。

- MeetUp名
- 通知基準までの残り時間
- 開催日時
- 集合時間（設定されている場合）
- 集合場所（設定されている場合）

残り時間は通知設定の値をそのまま表示せず、実際の送信時点から計算する。遅延した場合も正しい残り時間を表示する。

日時はDiscordのタイムスタンプ形式を使う。

## 7. 自動送信と遅延処理

### 7.1 通知時刻の許容誤差

通知予定時刻から15分以内であれば送信を許可する。

15分を超えた通知は送信しない。

また、15分以内でも集合時間（未設定なら開催日時）を過ぎていれば送信しない。

### 7.2 送信状態

少なくとも次の状態を管理する。

| 状態 | 意味 |
|---|---|
| PENDING | 送信待ち |
| SENDING | 送信処理中 |
| SENT | 送信成功 |
| FAILED | 送信失敗が確定 |
| SKIPPED | 条件により送信せず終了 |

失敗やスキップについては理由も記録する。

### 7.3 再試行

送信に失敗した場合は次の間隔で再試行する。

1. 1分後
2. 2分後
3. 4分後
4. 8分後

再試行を繰り返しても、元の通知予定時刻から15分を超えてはならない。最終枠は期限直前に1分の余裕を残した時刻までとし、それを超える再試行は行わない。

送信状態と再試行情報をデータベースに保持する。

### 7.4 Botの停止・再起動

Botが送信中に停止した場合は、再起動後に未完了の通知を検出する。

15分以内かつ通知基準日時より前なら再試行する。期限切れなら送信しない。

送信済みの通知は通常時に再送しない。Discordへの送信成功直後にBotが停止した場合など、送信結果が不明な通知は再試行を優先する。送信結果不明のまま期限切れになった通知は、失敗が確定していないため失敗扱いにせず、SKIPPEDとして記録して管理者への失敗通知は行わない。

### 7.5 複数通知が滞留した場合

同じMeetUpの複数の通知が、障害復旧などによって同時に送信対象となった場合、最も新しい通知だけを送信する。

古い通知はSKIPPEDとして記録する。

これは滞留した通知が同時に処理される場合に限る。正常稼働時は各通知を予定時刻に送信する。

## 8. 送信失敗時の管理者通知

リマインダーの送信に失敗し、最終的に送信できなかった場合は、主催者・共同主催者全員へDMを送信する。

DMには次の情報を含める。

- MeetUp名
- 本来の通知予定時刻
- 送信失敗が確定した時刻
- 失敗内容

意図的にOFFにした通知や、送信対象者がいない場合、期限切れでスキップした通知などは失敗通知の対象外とする。

### 8.1 DMが送れなかった場合

管理者のうち1人でも失敗通知のDMを受信できなかった場合、MeetUp専用チャンネルにも警告を投稿する。

複数人のDMが失敗しても、チャンネルへの警告は1件にまとめる。

### 8.2 チャンネルが利用できない場合

専用チャンネルにも警告を送れない場合は、警告を未送信状態で保存する。

チャンネルが復旧したら警告を送信する。

ただし、元の通知が最終的に失敗した時刻から24時間以内に限る。

24時間を超えた警告は送信せず、履歴だけ残す。

元のリマインダー自体は復旧時に再送しない。

### 8.3 MeetUp中止・アーカイブ時

MeetUpがCANCELLEDまたはARCHIVEDになった場合は、以下を停止する。

- 未送信の自動リマインダー
- リマインダーの再試行
- 未送信の失敗通知DM
- 未送信のチャンネル警告

過去の送信履歴は保持する。

## 9. Discordコマンドと設定画面

### 9.1 コマンドの変更

既存の `/meetupper remind` は削除し、手動通知機能も完全に廃止する。

新たに以下を実装する。

`/meetupper reminder [meetup]`

既存のMeetUp指定方式に合わせ、専用チャンネル内ではMeetUp IDを省略可能とする。

### 9.2 操作権限

主催者・共同主催者のみ設定画面を表示・操作できる。

参加確定者には設定変更権限を与えない。

### 9.3 設定画面

Discordの非公開応答（Ephemeral）で表示する。

設定画面には次の情報・操作を用意する。

- 現在の自動通知ON/OFF
- 現在の通知時刻一覧（最大5件）
- 各通知の予定時刻
- 各通知の送信状況
- ON/OFF切り替え
- 通知時刻の追加・変更・削除
- 選択式の通知時刻
- 自由設定の入力
- 保存
- キャンセル
- 履歴

Discordのボタン、セレクトメニュー、モーダルを適切に組み合わせて実装する。

### 9.4 保存処理

編集途中の内容はデータベースへ即時反映しない。

「保存」を押した時点で一括反映する。「キャンセル」では未保存の変更を破棄する。

複数人が同時に編集していた場合は、保存時に設定のバージョンを確認する。

他の管理者が先に保存していたら古い設定からの保存を拒否し、最新の設定を読み直すよう案内する。

設定変更を参加者へ通知する必要はない。

### 9.5 MeetUp作成時

`/meetupper create` には自動通知のON/OFFのみ追加する。初期値はON。

通知時刻の詳細設定は作成後の `/meetupper reminder` で行う。

## 10. 送信履歴

### 10.1 保存期間

送信履歴は90日間保存する。

対象には送信成功・送信失敗・スキップの履歴を含める。

90日を経過した履歴は自動削除する。

MeetUpが中止・アーカイブされた場合も、履歴の保存期間は変わらない。

### 10.2 表示方法

設定画面には現在の通知予定と送信状況を表示する。

過去の履歴は「履歴」ボタンから別画面で表示する。

- 新しい順に表示
- ページ切り替えに対応
- 保存期間内の全履歴を確認可能
- 日時変更前後の履歴を区別
- 送信・失敗・スキップを判別可能

日時変更で通知予定を再計算しても、変更前の履歴は削除しない。

## 11. データベース設計

現在の `reminders` テーブルは、通知種類と送信時刻だけを管理する単純な構造になっている。

新仕様では、少なくとも次の情報を管理できるよう設計し直す。

### MeetUp単位の設定

- 自動通知の有効・無効
- 設定された通知時間差（最大5件）
- 設定のバージョン

### 現在の通知予定

- 通知ID
- MeetUp ID
- 通知基準日時
- 通知予定時刻
- 送信状態
- 再試行回数
- 次回再試行時刻
- 送信結果・エラー情報

### 送信履歴

- 対象のMeetUp
- 対象となった基準日時
- 通知予定時刻
- 実際の送信時刻
- 最終状態
- 失敗・スキップ理由

### 失敗通知

- 対象の通知
- 管理者へのDM送信状況
- チャンネル警告の送信状況
- 警告の送信期限

通知設定・現在の通知予定・過去の履歴を適切に分離すること。

日時変更や通知設定の変更で、履歴が意図せず消えない構造とする。

保存・再計算・状態更新では、必要に応じてデータベースのトランザクションを使い、処理途中で矛盾が生じないようにする。

## 12. 実装時に守ること

1. 既存のMeetUpの参加管理や権限管理を壊さない。
2. PublicとPrivateの両方で同じリマインダー仕様を使用する。
3. 集合場所は従来どおり専用チャンネル内に限定する。
4. Bot再起動時に通知設定・未送信予定・再試行状態を復元できるようにする。
5. 通知の二重実行を抑制する。送信結果が不明な場合は再試行を優先する。
6. 設定保存時に通知予定を正しく更新する。
7. 古い手動リマインドのコマンド・関連処理を削除する。
8. 関連するREADME、設計書、コマンド一覧を新仕様に合わせて更新する。
9. 旧データ形式との互換性やマイグレーションは不要とする。

## 13. テスト要件

少なくとも以下のケースをテストすること。

- デフォルトONと初期通知3件
- OFF時に通知されないこと、設定保持、ONへの復帰
- 選択式と自由設定式、最大5件、最低1件、重複統合
- 集合時間優先と開催日時への切り替え
- 過去の集合時間・開催後の集合時間を拒否
- 作成時点で過ぎた通知を登録しない
- 開催日時・集合時間の変更による再計算と履歴保持
- 主催者のみの場合はスキップ
- 共同主催者または参加確定者がいる場合は通知
- 重複メンションの防止
- 通知の15分以内の遅延送信と期限切れ処理
- 送信失敗時の1分・2分・4分・8分の再試行
- Bot再起動時の未完了通知の復元
- 複数通知の滞留時に最新1件のみ送信
- 送信失敗時の管理者DM
- DM失敗時のチャンネル警告
- チャンネル復旧後24時間以内の警告送信
- 中止・アーカイブによる未送信処理の停止
- 非公開設定画面の権限確認
- 保存・キャンセル・同時編集時の競合検出
- 送信履歴の表示と90日後の削除
