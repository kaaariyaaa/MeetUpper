# 動作確認チェックリスト

実サーバーで確認する。チェックは各項目を上から順に実施する。UIの確認は、すべて応答が ephemeral であることを前提とする。

## 起動・環境

- [ ] `direnv allow` 後に `bun --version` が表示される
- [ ] `bun install` が成功する
- [ ] `bun run check` がエラーなしで終わる
- [ ] `bun test` が成功する
- [ ] `bun run build` が成功する
- [ ] `.env` に `DISCORD_TOKEN` を設定して `bun run start` で起動し、ログに `Logged in as ...` が出る
- [ ] 起動後に `/meetupper` が Discord に入力候補として表示される
- [ ] コマンドの入力候補に `[meetup]` 以外の引数（ユーザー・アクション・設定値）が表示されない
- [ ] 一般メンバーが `/meetupper init` を実行すると拒否され、確認パネルも操作できない
- [ ] 管理者が `/meetupper init` を実行すると確認パネルが表示され、「実行する」で `MeetUp` カテゴリ、`meetup募集` フォーラム、`招待` チャンネルが作成される
- [ ] `/meetupper init` の確認パネルで「キャンセル」を押すと何も作成されない
- [ ] 固定権限は `MeetUp` カテゴリに設定され、`meetup募集`・`招待` に個別の上書きが残らない
- [ ] `meetup募集` がカテゴリ最上部、`招待` が 2 番目にある
- [ ] init 前に `/meetupper create` を実行すると、init を促すメッセージが返る
- [ ] init を再実行してもチャンネルが重複しない

## UI共通

- [ ] すべての画面が実行者だけに表示される（他のメンバーには見えない）
- [ ] 画面・ボタン・エラーが日本語で表示される
- [ ] 他人が画面のボタン・セレクトメニュー・モーダルを操作すると拒否される
- [ ] 実行者が別サーバーから同じカスタムIDを操作しても拒否される
- [ ] 15分経過後に古い画面を操作すると、期限切れの案内とコマンド再実行の促しが表示される
- [ ] 画面を操作するたびに、ギルド・MeetUpの状態・権限が再確認される
- [ ] 主催者・共同主催者の権限を外した後、開きっぱなしの画面から管理操作すると拒否される
- [ ] アーカイブ済み・中止済みMeetUpで、状態を変える操作や編集操作をすると拒否される
- [ ] 退出・キック・主催者変更・中止・アーカイブ・招待送信は、確認ボタンを押すまで実行されない
- [ ] 完了後の画面に、詳細・編集・リマインダーなどへの導線が残る

## 作成モーダル

- [ ] `/meetupper create` でモーダルが1つだけ開き、公開モード・参加方法・MeetUp名・開催日時の4項目だけが表示される
- [ ] 公開モードで Public / Private を選べる
- [ ] 参加方法で直参加 / 主催者承認 / 参加者投票を選べる（Private では主催者承認固定）
- [ ] 開催日時を `YYYY-MM-DD HH:mm` で入力でき、`DEFAULT_TIMEZONE` どおりに解釈される
- [ ] 開催日時の形式が不正な場合はエラーになり、MeetUpは作成されない
- [ ] 作成直後は定員なし（0）・説明なし・集合情報なし・共同主催者なし・イベント連携OFFになる
- [ ] 作成直後の自動リマインダーがONで、1日前・3時間前・30分前が登録される
- [ ] 参加者投票を選んで作成した場合、必要票数が1で保存される
- [ ] 作成結果パネルに「MeetUpを開く」「編集」「リマインダー」が表示され、それぞれ該当画面へ移動する
- [ ] 作成したMeetUpが `/meetupper list` の該当タブに表示される

## 一覧・詳細・参加者一覧

- [ ] `/meetupper list` がダッシュボードを開き、募集中 / 参加中 / 管理中を切り替えられる
- [ ] 「募集中」には閲覧・参加申請できるACTIVEなMeetUpが表示される
- [ ] 「参加中」には自分が参加確定しているMeetUpが表示される
- [ ] 「管理中」には自分が主催者・共同主催者のMeetUpが表示される
- [ ] Private MeetUpは、招待・申請・参加の記録がある人にだけ表示される
- [ ] 一覧からMeetUpを選ぶと詳細パネルが開く
- [ ] 表示できるMeetUpがない場合、その旨と作成への導線が表示される
- [ ] `/meetupper show` の詳細パネルに、状態・公開モード・開催日時・参加状況が表示される
- [ ] 一般メンバーには参加ボタンと一覧へ戻る導線だけが表示される
- [ ] 参加確定者には退出・招待のボタンが表示される
- [ ] 主催者・共同主催者には編集・参加者一覧・招待・キック・集合情報・アーカイブ・中止・リマインダーが表示される
- [ ] 主催者だけに共同主催者・主催者変更のボタンが表示される
- [ ] `/meetupper members` が参加者と状態の一覧を表示し、前へ / 次へでページを切り替えられる
- [ ] 参加確定者・一般メンバーは `/meetupper members` を開けない
- [ ] `/meetupper show` の画面から編集・招待・キック・集合情報・退出・アーカイブ・中止・リマインダーへ移動できる（権限がある場合）

## Public MeetUp（主催者承認）

- [ ] 作成モーダルで Public・主催者承認を選んでMeetUpを作成できる
- [ ] 作成モーダルで Public・直参加を選んで作成でき、募集の参加ボタンで即座に参加確定する
- [ ] `/meetupper edit` で参加方法（直参加 / 主催者承認 / 参加者投票）を変更できる
- [ ] 非公開の専用チャンネルが作られ、主催者だけが閲覧できる
- [ ] `meetup募集` に募集投稿が作られ、参加申請ボタンが付いている
- [ ] スケジュールイベント連携を編集画面でONにすると Discord イベントが作成される
- [ ] 別メンバーが募集投稿の「参加申請」を押せる
- [ ] 申請通知が専用チャンネルに届き、主催者が「承認」できる
- [ ] 承認されたメンバーが専用チャンネルを閲覧・発言できる
- [ ] 承認されたメンバーの DM または通知で参加確定が伝わる
- [ ] 却下したメンバーは専用チャンネルを閲覧できない
- [ ] 辞退・キャンセルしたメンバーは専用チャンネルを閲覧できない（参加キャンセル時）
- [ ] 定員に達した後も参加申請自体は受け付けられる

## Public MeetUp（参加者投票）

- [ ] 作成モーダルで Public・参加者投票を選んで作成できる
- [ ] 作成直後の必要票数が1で、`/meetupper edit` から変更できる
- [ ] 参加申請に対して参加確定者が賛成票を押せる
- [ ] 投票制の参加申請でも主催者が「却下」できる
- [ ] 同じ人が二重投票できない
- [ ] 必要票数に到達した時点で自動的に承認される
- [ ] 承認後に専用チャンネルへ追加される

## Private meetup

- [ ] 作成モーダルで Private を選んでMeetUpを作成でき、募集フォーラムに投稿されない
- [ ] Private では参加方法が主催者承認固定で、参加者投票を選べない
- [ ] 主催者が `/meetupper invite` のユーザーセレクトでメンバーを招待でき、DM に招待ボタンが届く
- [ ] DM の「参加する」で参加確定し、専用チャンネルを閲覧できる
- [ ] DM の「参加しない」で辞退状態になる
- [ ] 辞退したユーザーが `/meetupper apply` で再申請でき、主催者が承認できる
- [ ] 招待を承諾すると専用チャンネルに「参加しました」の通知が投稿される
- [ ] 申請承認・投票・招待承諾のどの経路でも参加通知が投稿される
- [ ] 招待されていないユーザーは Private MeetUpへ申請できない
- [ ] 参加確定者が `/meetupper invite` を使うと、主催者承認待ちになる

## 招待・キック・共同主催者・主催者

- [ ] `/meetupper invite` がユーザーセレクトを表示し、選択後に確認パネルが出る
- [ ] 確認パネルで「キャンセル」を押すと招待が送られない
- [ ] 招待に失敗した対象は「招待中」のまま残らず、再招待できる
- [ ] 主催者が `/meetupper kick` で参加確定者だけを選択肢に表示できる
- [ ] キックの確認パネルで実行すると退出し、専用チャンネルの権限が外れ、参加者へ通知される
- [ ] 退出させられた人は `/meetupper apply` で再申請できず、再招待はできる
- [ ] キックの対象に主催者・共同主催者・一般メンバーは表示されない
- [ ] 主催者が `/meetupper cohost` で共同主催者を追加でき、一覧から削除できる
- [ ] 共同主催者は共同主催者の追加・削除を実行できない
- [ ] 主催者が `/meetupper host` で新しい主催者を選び、確認後に変更できる
- [ ] 主催者変更後、旧主催者の管理権限が外れ、新主催者に移る
- [ ] 自分自身・Bot・サーバー外のユーザーを選ぶとエラーになる
- [ ] 権限のないメンバーは招待・キック・共同主催者・主催者の画面を開けない

## DM 失敗時のフォールバック

- [ ] DM を拒否しているユーザーを招待すると、`招待` チャンネルにプライベートスレッドが作られる
- [ ] スレッドには招待対象者と Bot だけが参加している
- [ ] スレッド内の「参加する」「参加しない」で状態が変わる
- [ ] 回答後に一時スレッドが削除される
- [ ] DM もスレッドも失敗した場合、主催者側へ招待失敗が通知される
- [ ] 招待送信に失敗した対象は「招待中」のまま残らず、再招待できる

## 編集ハブ（保存式）

- [ ] `/meetupper edit` が設定ハブを開き、基本情報・参加方法・集合情報・イベント連携・共同主催者・主催者変更・リマインダーの導線が表示される
- [ ] 名前・説明・定員・開催日時を変更できる
- [ ] 参加方法と必要票数を変更できる（Private は主催者承認固定）
- [ ] 変更しただけではDBに反映されず、「保存」で一括反映される
- [ ] 「キャンセル」で未保存の変更が破棄される
- [ ] 開催日時を変えるとリマインダーの通知予定時刻が更新される
- [ ] 開催日時を変えると連携スケジュールイベントの開始日時が更新される
- [ ] 名前・開催日時を変えると Public の募集投稿（スレッド名・埋め込み・参加ボタン）も更新される
- [ ] 定員を確定済み参加者数より小さい値に変更すると警告が出て、既存の参加確定は取り消されない
- [ ] 共同主催者・主催者変更・リマインダー設定へ編集ハブから移動できる
- [ ] 権限のないメンバーは編集ハブを開けない

## 集合情報

- [ ] `/meetupper info` が集合時間・集合場所の入力モーダルを開く
- [ ] 保存すると参加者へ通知される
- [ ] 集合場所は参加確定者だけが閲覧できる（未確定者・一般メンバーには見えない）
- [ ] アーカイブ後は集合情報を変更できない
- [ ] 権限のないメンバーは集合情報の画面を開けない

## 退出・アーカイブ・中止の確認

- [ ] `/meetupper leave` が参加キャンセルの確認パネルを開き、「キャンセルする」で退出する
- [ ] 確認パネルで「やめる」を押すと状態が変わらない
- [ ] 主催者・共同主催者は自分自身の参加キャンセルができない
- [ ] 文脈なしで `/meetupper leave` を実行すると参加中のMeetUp一覧が表示される
- [ ] `/meetupper archive` が確認パネルを出し、実行すると状態が ARCHIVED になる
- [ ] `/meetupper cancel` が確認パネルを出し、実行すると状態が CANCELLED になり参加者へ通知される
- [ ] 中止済み（CANCELLED）のMeetUpもアーカイブでき、アーカイブ済みは再アーカイブできない
- [ ] 権限のないメンバーは退出・アーカイブ・中止の画面を開けない

## リマインダー

- [ ] MeetUp作成時点で自動通知がON・1日前/3時間前/30分前の3件で登録される
- [ ] 作成後に `/meetupper reminder` でOFFにでき、通知時刻の設定は保持される
- [ ] OFFのまま通知予定時刻を過ぎても送信されず、後からONにしても過去分は送信されない
- [ ] 通知基準は集合時間が優先され、未設定のときは開催日時に切り替わる
- [ ] 開催日時・集合時間の変更で通知予定が再計算され、送信履歴は残る
- [ ] 通知時刻の設定だけを変更しても、送信済みの通知は再送されない
- [ ] 主催者のみのMeetUpでは通知がスキップされる
- [ ] 共同主催者・参加確定者がいると主催者を含めて通知され、重複メンションは1回になる
- [ ] キャンセル・辞退・キックされたメンバーは通知対象から外れる
- [ ] 通知予定時刻から15分以内なら遅延送信され、15分を超えると送信されない
- [ ] 残り時間は実際の送信時刻から計算され、「集合まで○分」「開催まで○分」が切り替わる
- [ ] 送信失敗時に1分・2分・4分・8分後へ再試行され、15分を超える再試行は行われない
- [ ] 最終的に失敗すると主催者・共同主催者へDMが届く
- [ ] DMが1人でも失敗すると専用チャンネルへ警告が1件だけ届く
- [ ] チャンネルへ警告を送れない場合は保持され、24時間以内の復旧で送信される
- [ ] 25時間後に復旧しても警告は送信されず、期限切れとして残る
- [ ] Botを再起動すると、15分以内かつ通知基準日時より前の未完了通知だけ再送される
- [ ] 予定時刻から15分を過ぎた未送信の通知は再起動後も送信されず、スキップとして残る
- [ ] 送信結果不明のまま期限切れになった通知は、失敗DMを送らずスキップとして記録される
- [ ] 複数の通知が同時に滞留した場合、最新の1件だけ送信され、他はスキップされる
- [ ] アーカイブ・中止で未送信の通知・再試行・DM・警告が停止し、履歴は残る
- [ ] 旧 `/meetupper remind`（手動リマインド）がコマンド一覧に存在しない

## リマインダー設定画面

- [ ] `/meetupper reminder` が ephemeral で開き、主催者・共同主催者だけが操作できる
- [ ] 参加確定者は設定画面を開けない
- [ ] ON/OFF・通知時刻一覧・予定時刻・送信状況が表示される
- [ ] 選択式9種類と自由設定（日・時間・分、最短1分前）を追加でき、併用できる
- [ ] 同一時間差は1件に統合され、最大5件に制限される
- [ ] ONのときは最低1件必要で、最後の1件はOFFにしないと削除できない
- [ ] 設定済みの通知時刻を変更でき、予定時刻と表示が更新される
- [ ] 編集途中ではDBが変わらず、「保存」で一括反映される
- [ ] 「キャンセル」で未保存の変更が破棄される
- [ ] 別の管理者が先に保存した場合、古い設定からの保存が拒否され、再読み込みを促される
- [ ] 履歴ボタンで新しい順に表示され、ページ切り替え・状態・理由・日時変更前後の基準日時が確認できる
- [ ] 90日を超えた履歴が自動削除される

## アーカイブ・中止の反映

- [ ] アーカイブでチャンネル名の先頭に `archive-` が付く
- [ ] 主催者のチャンネル管理権限が外れる（サーバー管理者権限は別扱い）
- [ ] アーカイブ後も参加確定者は閲覧・発言できる
- [ ] アーカイブ後は新規申請・招待・リマインダーが止まる
- [ ] アーカイブ時に連携スケジュールイベントが「キャンセル済み」になる
- [ ] 中止後は新規申請・招待・リマインダーが止まる
- [ ] 中止後、連携スケジュールイベントが「キャンセル済み」になり、公開履歴が残る
- [ ] 専用チャンネル内で `[meetup]` を省略して `/meetupper cancel` を実行すると、その専用チャンネルのMeetUpが対象になる
- [ ] `[meetup]` を取る各コマンドは、専用チャンネル／募集スレッド内で `[meetup]` を省略して実行できる

## チャンネル削除復旧

- [ ] 専用チャンネルを Discord 上で直接削除すると、Bot が再作成する
- [ ] 再作成後に参加確定者の権限が再設定される
- [ ] 主催者に「中止する / ACTIVE を維持する」の確認が出る
- [ ] 「中止する」で CANCELLED になる
- [ ] 「ACTIVE を維持する」で状態が維持される

## カテゴリ上限

- [ ] カテゴリ内のチャンネル数が 50 に達すると、`MeetUp-2` 以降が作成される
- [ ] 移動対象はアーカイブ済みチャンネルが優先される
- [ ] `meetup募集` と `招待` は元のカテゴリに残る
- [ ] 移動後もチャンネル名・履歴・参加者権限が維持される
- [ ] 承認・キャンセルなどで権限を同期しても、管理者が追加したロール単位の権限上書きは消えない

## 権限

- [ ] 主催者以外の一般メンバーは専用チャンネルを閲覧できない
- [ ] 主催者・共同主催者が参加承認・却下・招待・集合情報変更・アーカイブを実行できる
- [ ] 共同主催者は共同主催者管理・主催者変更を実行できない
- [ ] 参加確定者が参加キャンセル・招待申請・投票を実行できる
- [ ] 主催者は自分自身の参加キャンセルができない
- [ ] 主催者変更後、旧主催者の管理権限が外れる
- [ ] 管理者以外は `/meetupper init` を実行できない
- [ ] Private MeetUpは招待・申請・参加済みの人だけが一覧・詳細で閲覧できる
- [ ] 各画面の操作ボタンは、実行者に権限がある場合だけ表示される
