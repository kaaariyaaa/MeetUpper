# 実装上の決定事項

設計書 21 章の未決定点と、実装で単純化した点を記録する。仕様変更はここを更新してから実装する。

## 設計書 21 章への回答

| 項目 | 決定 |
| --- | --- |
| 定員到達後の承認 | 定員超過の承認を許可する。承認時に主催者へ「定員を超えています」と警告を表示する。自動キャンセル待ちは作らない。 |
| 参加方法（直参加 / 申請参加） | `approval` オプションで選ぶ。省略時は直参加。直参加は募集ボタンから即座に参加確定し、申請参加は主催者承認（または参加者投票）を経る。招待制（PRIVATE）は主催者承認固定。 |
| Private の再参加申請 | 過去に招待されたユーザー（`INVITED` / `DECLINED` の記録があるユーザー）は `/meetupper apply` で再申請できる。主催者または共同主催者が承認する。 |
| Discord スケジュールイベント | 終了予定日時は開始 + 2 時間で固定する。場所は「参加確定者に共有します」とし、正確な集合場所は公開しない。 |
| 権限の優先関係 | アーカイブ時に外すのはチャンネル固有の `ManageChannels` のみ。サーバー全体の管理権限・Administrator は変更しない。 |
| サーバー全体の上限 | カテゴリの 50 上限は `MeetUp-N` の自動作成で回避する。サーバー全体のチャンネル上限に達した場合は作成に失敗するため、エラーを返して手動整理を促す。 |

## 実装上の単純化

- 自動リマインダーはMeetUpごとにON/OFF・通知時刻（ONは1〜5件、OFFは0件可）を設定でき、既定はONで1日前・3時間前・30分前。詳細は [REMINDERS_SPEC.md](REMINDERS_SPEC.md)。
- 通知基準は集合時間を優先し、未設定なら開催日時。通知予定時刻から15分以内のみ送信し、失敗時は1分・2分・4分・8分後に再試行する。再試行は15分の期限直前に1分の余裕を残し、期限を超える場合は行わない。
- 通知対象は主催者・共同主催者・参加確定者（重複排除）。主催者以外に誰もいない通知は送信せずスキップとして記録する。
- 最終送信失敗時は主催者・共同主催者へDMし、DM失敗時は専用チャンネルへ1件の警告を送る。警告は失敗から24時間以内に送信する。
- 送信履歴は90日保持し、日時変更や設定変更では削除しない。中止・アーカイブ時は未送信の通知・再試行・DM・警告を停止する。
- Bot再起動後、未完了の通知は予定時刻から15分以内かつ通知基準日時より前のものだけ再送する。期限切れは送信せずSKIPPEDとして記録する。送信結果不明のまま期限切れになった通知も失敗扱いにせず、管理者へ失敗DMを送らない。
- 手動リマインド（`/meetupper remind`）は廃止した。
- `/meetupper reminder` の設定画面は非公開応答で開き、主催者・共同主催者だけが操作できる。編集は下書きとして保持して保存時に一括反映し、設定バージョンが変わっていれば古い保存を拒否する。
- 開催日時・集合時間の変更では、通知基準日時が変わった場合だけ通知予定を再計算する。送信済みの履歴は保持する。
- 日時入力は `YYYY-MM-DD HH:mm`（`DEFAULT_TIMEZONE` 基準）または ISO 8601（オフセット付き）を受け付ける。保存は UTC。
- スケジュールイベントの更新はMeetUp名・説明・開始日時のみ。場所は公開しない方針のため同期しない。
- 専用チャンネルが削除された場合、再作成後に主催者向けの確認メッセージを新チャンネルへ投稿する。DM には同じ情報を送るが、操作ボタンは新チャンネル側だけに付ける。
- アーカイブ・中止の確認はボタンで行う。コマンド実行だけでは状態を変更しない。
- 招待の一時スレッドは `招待` チャンネルのプライベートスレッド。回答後に削除する。無回答のままのスレッドは Discord の自動アーカイブに任せる。
- 参加確定者による招待は、主催者・共同主催者の承認後に DM を送る。承認待ちの招待申請は DB に保持する。
- 中止後も専用チャンネルは残す。アーカイブは別操作とする。
- `/meetupper cancel` は主催者・共同主催者が実行できる（権限を触らず、参加者へチャンネルとDMで通知する）。
- アーカイブは ACTIVE と CANCELLED のMeetUpに対して実行できる（中止済みの後片付け用）。ARCHIVED は最終状態とし再実行できない。
- 主催者変更では旧主催者を共同主催者に残さず、専用チャンネル権限も新主催者へ移す。
- 開催日時の変更は `/meetupper edit` で行い、通知基準日時が変わったときにリマインダーを再計算してスケジュールイベントも同期する。
- 定員を確定済み参加者数より小さい値へ変更できる。その場合は警告を表示し、既存の参加確定は取り消さない。
- 直参加のMeetUpでは、募集の参加ボタンでその場で参加確定し、専用チャンネルへ参加通知を投稿する（定員超過は警告のみ）。
- `/meetupper edit` で参加方法や名前・日時を変更したときは、募集投稿の埋め込みと参加ボタン（文言含む）も更新する。
- Private MeetUpの承認方式は常に主催者承認とし、参加者投票は Public のみに適用する。
- 定員（`capacity`）は任意で、省略時は 0（定員なし）として保存する。定員 0 のMeetUpは定員超過の警告を出さない。
- `/meetupper list` は Public の全件と、Private のうち実行者が招待・申請・参加したものを表示する。
- MeetUp中止時、連携スケジュールイベントは削除せず「キャンセル済み」に変更して公開履歴を残す。
- 参加者投票は Public のみ。投票には参加確定者が必要なため、主催者・共同主催者が招待で最初の参加確定者を用意する。`required-votes` は参加者投票を選ぶ場合に必須。
- Discordスケジュールイベント連携は作成時に `event:true` を指定した Public のみ有効（既定は無効）。
- アーカイブ時、連携中のスケジュールイベントは「キャンセル済み」に変更して公開履歴を残す。
- 招待DMと招待スレッドの両方に失敗した場合は参加状態を招待前に戻し、再招待できるようにする。
- 参加が確定したら、経路（申請承認・参加者投票・招待承諾）を問わず専用チャンネルへ「<@user> が参加しました（確定 N人）」を投稿する。
- 主催者・共同主催者は `/meetupper kick` で参加確定者を退出させられる。状態は KICKED とし、本人の再申請は不可（主催者からの再招待は可）。
- Bot のメッセージはすべて embed で表示する（共通の色は 0x5865f2）。メンションで通知する必要があるリマインダーなどは、本文を embed にしたうえでメンションだけを `content` に残す。
- 参加確定・キャンセルなどで権限を同期するとき、Bot は参加者個人の上書きだけを管理し、管理者が設定したロール単位の上書きは残す。
- `meetup募集` と `招待` の固定権限（全員が閲覧可、チャンネルへの直接投稿は不可、スレッド投稿は可）は `MeetUp` カテゴリ側に設定し、両チャンネルは個別の上書きを持たずカテゴリから継承する。カテゴリ配下のMeetUp専用チャンネルは従来どおり個別の権限で非公開にする。
